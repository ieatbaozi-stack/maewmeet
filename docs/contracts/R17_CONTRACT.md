## 0. สภาพปัจจุบัน (main อ่านโค้ด 2026-11-19)
- **กลุ่ม:** ลบแบบ soft (`groups.deleted_at`) · ข้อมูลทั้งหมดยังอยู่ **ตลอดไป** · ทุก query ผูก `deleted_at IS NULL` → สมาชิกเข้าไม่ได้ทันที · super admin เห็นในหน้า admin (ตัวกรอง "ลบแล้ว") แต่**กู้ไม่ได้** · FK จาก `group_member`, `group_invite`, `appointment` เป็น `ON DELETE CASCADE` → ลบถาวรได้ด้วย `DELETE FROM groups`
- **บัญชี:** ลบแล้ว**ล้างข้อมูลส่วนตัวทันที** (`markUserDeletedGuarded` + `purgeDeletedUserFootprint`): PIN, ชื่อ, username, LINE, session, สมาชิกภาพ, busy, routine, RSVP, แจ้งเตือน, ชื่อในแจ้งเตือนของคนอื่น · เหลือแถว `user` ว่างๆ (status `deleted`) ไว้ให้ FK ของนัด/audit · **กู้คืนไม่ได้แล้วตั้งแต่ตอนกด** → ตรงกับสิทธิ์ลบข้อมูล (PDPA) ดีกว่าแบบเก็บไว้
- ดังนั้น "เก็บ 30 วันแล้วกู้ได้" สำหรับบัญชี = ต้อง**เก็บข้อมูลส่วนตัวไว้ 30 วันแทนที่จะลบทันที** ซึ่งเปลี่ยนทิศของนโยบายเดิม → ให้ boss ยืนยันใน B1
