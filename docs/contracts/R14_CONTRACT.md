## 1. สิ่งที่เปลี่ยน
### 1.1 สำหรับผู้ใช้
- ลง busy ซ้ำเป็นชุด (routine) ได้: เลือก **วันในสัปดาห์** (เช่น จ.–ศ., จ. อ. พฤ. ศ.) + **เวลา** หรือทั้งวัน + **ช่วง**
- ช่วงเลือกได้สองแบบ: **สัปดาห์ถึงสัปดาห์** (แสดงเป็นช่วงวันที่ เช่น "16–22 พ.ย." ไม่ใช้เลขสัปดาห์) หรือ **เดือนถึงเดือน** · สัปดาห์เริ่มวันจันทร์ (B8)
- ปุ่มทางลัดชุดแรก (B1) — ทุกปุ่มเติมค่าให้แล้วแก้วัน เวลา ชื่อได้ก่อนบันทึก:

  | ปุ่ม | ค่าเริ่ม |
  |---|---|
  | ทำงาน | จ.–ศ. 09:00–18:00 |
  | เรียน/คลาส | จ.–ศ. เวลาให้เลือกเอง |
  | ยิม | วันและเวลาให้เลือกเอง |
  | เสาร์–อาทิตย์ | ส. อา. ทั้งวัน |
  | สร้างเอง | ว่าง |

- ตัวเลือกช่วงมีปุ่มลัด **"ทั้งเดือนนี้"** = routine ใช้ตลอดเดือนนี้ (B2) · ux เพิ่มปุ่มลัดช่วงอื่นได้ เช่น "4 สัปดาห์ข้างหน้า"
- ก่อนบันทึกแสดงสรุป "จะลง N วัน" และบอกชัดว่า **ทุกกลุ่มที่คุณอยู่จะเห็นช่วงนี้** (D5)
- หน้ารายการ busy ของฉันมีส่วน routine แยกจาก busy เดี่ยว (แสดงชื่อ วัน เวลา ช่วง จำนวนวันที่เหลือ)
- แก้หรือลบ (B4, B5) ให้เลือกขอบเขต:
  - **เฉพาะวันนี้** — ลบวันเดียว หรือแก้วันเดียว (วันนั้นแยกเป็น busy เดี่ยว)
  - **ตั้งแต่สัปดาห์/เดือนที่เลือกไป** — วันก่อนหน้าคงเดิม
  - **ทั้งหมด** — แก้ = ทุกวันที่ยังไม่ผ่าน · ลบ = หายทั้งหมดรวมวันที่ผ่านมาแล้ว
- กะข้ามเที่ยงคืนได้ (B6) เช่น 22:00–06:00 นับเป็นของวันที่เริ่ม (เลือก "จันทร์" = จันทร์ 22:00 ถึงอังคาร 06:00) · จบ 24:00 ได้
- คนอื่นในกลุ่มเห็นวันของ routine เป็น busy ธรรมดา กติกาซ่อนรายละเอียดเดิมทุกอย่าง ไม่รู้ว่ามาจาก routine

### 1.2 เพดาน (B3, B7)
| เรื่อง | ค่า |
|---|---|
| ช่วงต่อ routine | ≤ 26 สัปดาห์ หรือ ≤ 6 เดือน · ต้องมีวันจบเสมอ · ต่ออายุได้ (แก้วันจบ) |
| วันจบไกลสุด | ≤ วันนี้ + 12 เดือน |
| routine ที่ยังไม่จบต่อคน | ≤ 10 |
| วันของ routine ในอนาคตต่อคน | ≤ 1,500 (architect เสนอ กันกรณีเต็ม 10 routine ทุกวัน) |
| busy เดี่ยว | ≤ 300 เท่าเดิม · วันของ routine **ไม่นับ** · วันที่แก้แยกออกมาเริ่มนับ |
| วันในอดีต | เลือกช่วงเริ่มในอดีตได้ (เช่น "เดือนนี้" ตอนกลางเดือน) แต่สร้างวันตั้งแต่วันนี้ไปเท่านั้น |

### 1.3 ฝั่งเซิร์ฟเวอร์ (ตาม ADR 0012 §4–§7)
- ตารางใหม่ `busy_routine` (กฎ) และ `busy_routine_skip` (วันที่ถูกลบ/แยก) · คอลัมน์ใหม่ `busy_block.routine_id` (nullable ไม่ backfill)
- บันทึก routine = เก็บกฎ + สร้างแถว `busy_block` ทุกวันในช่วง ใน transaction เดียว (ได้ทั้งหมดหรือไม่ได้เลย) · ปฏิทินกลุ่ม วันว่างร่วม เตือนนัดทับ ใช้ทางอ่านเดิม ไม่แก้
- ขยายวันด้วยฟังก์ชัน pure ใหม่ใน `src/lib/calendar` (`routineRange`, `expandRoutine`) ทีละวันแบบเวลาผนัง (กฎ 9) · เวลาที่ไม่มีจริง (DST) = ปฏิเสธทั้งคำขอ
- API ใหม่ `GET/POST /api/me/busy-routines`, `PATCH/DELETE /api/me/busy-routines/:id` (รับ `from`) · `PATCH/DELETE /api/me/busy/:id` เดิมบนแถว routine = แยก/ลบวันเดียว + บันทึก skip
- เจ้าของเท่านั้นทุก action · SA ก็แก้ไม่ได้ · ทุกคำสั่ง SQL ผูก `user_id` ของผู้กระทำ · id คนอื่น = `NOT_FOUND` · body zod `.strict()` (กฎ 6)
- `routine_id`, `weekdays`, ช่วง และตารางกฎ ไม่ออกไปถึงคนอื่นเลย
- เพดานนับในคำสั่งเขียนเดียว ไม่มี check-then-act · `windowCount` นับเฉพาะ `routine_id IS NULL`
- ลบบัญชี (`account.ts`) ต้องลบ routine เอง เพราะบัญชีถูก anonymize ไม่เกิด cascade · cron (`maintenance.ts`) ลบ routine ที่จบเกิน 90 วัน
- ADR 0010 (`kind:'daily'`, `series_id`) ใช้ต่อเหมือนเดิม ไม่รื้อ

## 2. ไม่ทำ
- routine ไม่มีวันจบ · กฎรายเดือนแบบ "วันที่ 15 ของทุกเดือน" · RRULE เต็มรูป · นำเข้าจากปฏิทินอื่น
- ช่องเลือก timezone ใน UI (ใช้ Asia/Bangkok เหมือนเดิม เก็บ `tz` ต่อ routine ไว้)
- เปลี่ยน `kind:'daily'` เดิมให้เป็น routine
- ลบตาราง `place_search_cache` (ค้างจาก R13 ทำรอบหลัง)

## 5. ความเสี่ยงที่ต้องวัด

## 9. boss ตัดสินเพิ่มหลังผลวัด perf (2026-11-11, "ใช้ตามที่แนะนำ")
ผลวัดของ platform (libSQL ในเครื่อง, กลุ่ม 50 คน): 2 routine จ.–ศ./คน ใช้ 93% ของ `CALENDAR_MAX_ITEMS` ที่วันว่าง 62 วัน · 4 routine/คน = 140% ถูกตัด (`truncated`) วันว่างผิด
- **B11 (ก)+(ค):** ทางคำนวณวันว่างร่วมและเตือนนัดทับใช้เพดานแยก 32,000 แถว (ไม่ส่งทุกชิ้นให้ client) · ปฏิทินกลุ่มที่ส่งรายการให้ client คงเพดาน 5,000 · และรวมช่วงที่ติด/ทับกันของคนเดียวกันก่อนป้อน `commonFreeTime` (ผลวันว่างต้องเท่าเดิมทุกกรณี มีเทสต์เทียบ) · perf test ต้องแสดงว่ากรณี B ไม่ถูกตัดในทางวันว่าง
- **B12:** การแก้ "ตั้งแต่สัปดาห์/เดือนนี้ไป" ที่แยกเป็นสองชุด **ไม่นับ** เพดาน 10 ชุด (เป็น routine เดิม) · การสร้างใหม่ยังนับ 10 · เพดาน 1,500 แถวยังใช้กับทุกกรณี
- cron ลบ routine ที่จบเกิน 93 วัน (90 + 3 ให้แถวหมดอายุก่อน) แทน 90 ใน ADR — main รับ
