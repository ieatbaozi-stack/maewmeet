## 1. เตือนก่อนนัด
### 1.1 ใครได้รับ
เฉพาะสมาชิกปัจจุบันของกลุ่มที่ตอบ **"ไป"** ณ เวลาที่เตือนถึงกำหนด (boss เลือก 2026-11-09) · "อาจไป" / "ไม่ไป" / ยังไม่ตอบ ไม่ได้รับ
- ผู้รับได้แจ้งเตือนใน**กระดิ่ง** · คนที่เชื่อม LINE แล้วได้ใน **LINE** ด้วย
- เปลี่ยนจาก "ไป" เป็นอย่างอื่นก่อนส่งจริง = ไม่ส่ง (ตรวจซ้ำพร้อมสถานะนัดใน §1.4)
- **คำถามยืนยันในกระดิ่งเท่านั้น** (boss เพิ่ม 2026-11-09): สมาชิกปัจจุบันที่ตอบ "อาจไป" หรือ**ยังไม่ตอบ** ณ เวลาถึงกำหนด ได้ 1 ครั้ง · คนตอบ "ไม่ไป" ไม่ได้รับ · **ไม่ส่ง LINE ไม่กินโควตา**

### 1.2 เมื่อไร
| ชนิด | ถึงกำหนด | เงื่อนไขส่ง |
|---|---|---|
| `appointment.reminder_1d` | `startAt − 24 ชม.` · ถ้าตกช่วงเงียบ 22:00–07:59 (เวลาท้องถิ่นของนัด) เลื่อนไป 08:00 ถัดไป | ถึงกำหนดแล้ว และเหลือเวลาก่อนเริ่ม ≥ 3 ชม. |
| `appointment.reminder_1h` | `startAt − 60 นาที` (ไม่มีช่วงเงียบ) | ถึงกำหนดแล้ว และเหลือเวลาก่อนเริ่ม ≥ 15 นาที |
| `appointment.rsvp_nudge` (กระดิ่งเท่านั้น) | เหมือน `reminder_1d` รวมช่วงเงียบ | เหมือน `reminder_1d` |

กรณีพิเศษ (boss เห็นชอบ 2026-11-09):
| กรณี | ผล |
|---|---|
| สร้างนัด/เลื่อนเวลาหลังเวลาถึงกำหนดของชนิดนั้น (`scheduled_at > due`) | ข้ามชนิดนั้น · สร้างกระชั้น < 1 วัน = ข้าม 1d · < 1 ชม. = ไม่มีเตือน |
| นัดถูกยกเลิก | ไม่ส่ง ตรวจซ้ำก่อนส่งจริงทุกครั้ง รวมที่ค้างในคิว |
| นัดช่วงเช้ามาก | 1d ไม่เด้งกลางดึก (ช่วงเงียบด้านบน) |
| แก้วันหรือเวลานัด | เตือนตามเวลาใหม่ · รายการเก่าที่ค้างคิวไม่ส่ง |
| ตัวตั้งเวลาพลาดหลายรอบ | ไม่ส่งย้อนหลังเกินเงื่อนไขในตาราง |

- คำนวณเวลาด้วย `src/lib/calendar` เท่านั้น (กฎ 9) · ใช้ `tz` ของนัด
- ห้ามส่งซ้ำ: ตาราง `appointment_reminder` PK `(appointment_id, kind, start_at)` เขียนใน transaction เดียวกับ `notify()` · รันซ้ำ/พร้อมกันต้องได้ผลเดิม

### 1.3 กระดิ่งในแอป (boss ระบุ)
- เพิ่ม 3 ชนิด (`reminder_1d`, `reminder_1h`, `rsvp_nudge`) ใน `notify()` ตาม ADR 0007 · `rsvp_nudge` ไม่เขียน outbox · ถ้อยคำถามแบบไม่กดดัน เช่น "คุณยังไม่ได้ยืนยัน จะไปไหม?" · params เป็นค่าดิบ `{groupId, groupName, appointmentId, title, startAt, tz}` · แสดงในกระดิ่งและหน้า `/notifications` · กดแล้วไป `/appointments/<id>` · TH/EN ครบ · นับ badge ตามเดิม
- ข้อความแสดงวันเวลาจริง ไม่ใช้คำว่า "พรุ่งนี้" แบบตายตัว ถ้าไม่ตรงวันจริง

### 1.4 LINE
- `notify()` เขียน `notification_outbox` (`channel='line'`) สำหรับผู้ที่เชื่อมแล้ว · แปลตาม `user.locale` ตอนส่ง
- ส่งด้วย Push API ทีละคน · ใส่ `X-Line-Retry-Key` กันส่งซ้ำ · retry ≤ 5 ครั้ง backoff ตาม ADR 0007
- ก่อนส่งตรวจว่านัดยัง `active` และ `startAt` ตรงกับตอนเข้าคิว ไม่ตรง = ไม่ส่ง
- โควตาเดือนหมด (429 monthly limit) → ไม่ retry ซ้ำในเดือนนั้น · log จำนวน ไม่ log เนื้อหา · กระดิ่งยังทำงานปกติ
- ข้อความมีแค่ชื่อนัด วันเวลา ชื่อกลุ่ม ลิงก์นัด (`?openExternalBrowser=1`) · **ไม่ส่งสถานที่ รายละเอียด ชื่อสมาชิก**

### 1.5 ตัวตั้งเวลา
- `/api/cron/reminders` ทุก 15 นาทีด้วย **Vercel Schedules** ใน `vercel.json` (Hobby ทำได้ · ~2,900 รอบ/เดือน จากเพดาน 5,000) · ป้องกันด้วย `CRON_SECRET` แบบเดียวกับ `/api/cron/daily`
- จำกัดงานต่อรอบ ไม่ให้ function หมดเวลา · ที่เหลือไปรอบถัดไป
- ops ตรวจบน preview: ทำงานจริงไหม ส่ง `CRON_SECRET` มาไหม preview กินรอบเพิ่มไหม · Schedules ยังเป็น beta ถ้าใช้ไม่ได้ เสนอ main เปลี่ยนเป็น cron-job.org โดยไม่แก้ endpoint

## 2. เชื่อมบัญชี LINE
1. `/me` → "เชื่อมต่อ LINE" → แอปสร้างโค้ดสุ่ม ใช้ได้ครั้งเดียว อายุ 10 นาที แสดงพร้อมปุ่ม/QR เพิ่มเพื่อน OA
2. ผู้ใช้ส่งโค้ดในแชท OA → webhook ผูก `user.line_user_id` แล้ว **reply** ยืนยัน (ไม่กินโควตา)
3. `/me` แสดงสถานะ + "ยกเลิกการเชื่อมต่อ"

ความปลอดภัย:
- `POST /api/line/webhook` ตรวจ `X-Line-Signature` (HMAC-SHA256 ด้วย channel secret แบบ timing-safe) กับ raw body ก่อนทำอะไร · ลายเซ็นผิด = 401 ไม่ประมวลผล
- เก็บแค่ hash ของโค้ด · ห้าม log โค้ด/token/LINE user id · rate limit การสร้างโค้ดและการลองโค้ด
- 1 LINE ผูกได้ 1 บัญชี (unique index มีแล้ว) · ชนกัน = ปฏิเสธ
- `unfollow` → ยกเลิกการผูกและล้างคิวที่ค้างของผู้ใช้นั้น
- ข้อความอื่นที่ไม่ใช่รูปแบบโค้ด: webhook เงียบ เพื่อไม่ทับปุ่ม "วิธีใช้งาน" (auto-response คีย์เวิร์ด) และแชทมือของ boss
- API ของ `/me` ตรวจ session ที่เซิร์ฟเวอร์ (กฎ 6) · ความลับอยู่ใน env เท่านั้น (กฎ 7)
- ไม่มีค่า env LINE = ช่องทางปิดเงียบ แอปทำงานปกติ · preview ไม่ใส่ค่า จึงไม่ส่งถึงคนจริง
