## Context
PRD §5: "ช่วงว่างในวัน = หน้าต่าง − ยูเนียน busy ของสมาชิกปัจจุบันทุกคน · แสดงช่วง ≥ ขั้นต่ำ · busy ทั้งวันปิดทั้งวัน · busy ข้ามวันแบ่งคิดตามวันท้องถิ่น" · D9: หน้าต่าง 08:00–22:00, ขั้นต่ำ 2 ชม., ปรับต่อกลุ่มได้ · U9.1: ไม่ว่างครบให้บอก "ว่าง X/Y" + ใครติด

## Decision

### 1. นิยาม
- **สมาชิกที่นับ** = แถว `group_member` ณ เวลาที่คำนวณ (สมาชิกปัจจุบัน) — ไม่ย้อนดูประวัติ: คนที่ออกแล้วไม่ถูกนับแม้ในวันอดีต, คนเพิ่งเข้าถูกนับทุกวัน · super admin ที่ไม่ใช่สมาชิก **ไม่ถูกนับ** (PRD §3)
- **หน้าต่างของวัน D** = `[D@start, D@end)` เป็นเวลาบนนาฬิกาใน `groups.tz` (`end = 1440` = เที่ยงคืนถัดไป) → แปลงเป็น instant ผ่าน `dayWindow()` (ADR 0004)
- busy **timed** ทำงานบน instant (ครึ่งเปิด) แล้ว clip เข้าหน้าต่าง → busy ข้ามเที่ยงคืนถูก "แบ่งตามวันท้องถิ่น" โดยอัตโนมัติ
- busy **ทั้งวัน** ทำงานบน **วันที่ลอย**: ปิดวัน D ทั้งวันถ้า `local_start_date ≤ D ≤ local_end_date` (ไม่แปลง tz)
- **ว่างร่วม (all_free)** ⇔ ไม่มีสมาชิกคนใดติด busy ทั้งวันใน D **และ** มีช่วงว่างร่วม ≥ `min_free_minutes` อย่างน้อย 1 ช่วง
- **สมาชิก m ว่างในวัน D** (ใช้นับ X/Y) ⇔ m ไม่ติดทั้งวัน และ `หน้าต่าง − busy ของ m` มีช่วง ≥ ขั้นต่ำ — ใช้กฎเดียวกับกลุ่ม แต่คิดคนเดียว
- ช่วงที่ยาว **เท่ากับ** ขั้นต่ำพอดีนับว่าผ่าน (≥) · busy ที่แตะขอบ (จบ 10:00 / เริ่ม 10:00) ไม่ทับกัน
- การตั้งค่ากลุ่ม (validation ตอน `group.update`): `0 ≤ start < end ≤ 1440`, ทั้งสองค่าหาร 30 ลงตัว, `30 ≤ min_free ≤ end − start` และหาร 30 ลงตัว · **v1 ไม่รองรับหน้าต่างข้ามเที่ยงคืน** (เช่น 18:00–02:00)

### 2. Pseudo-code
```text
function commonFreeTime(group, members, busyBlocks, fromDate, toDate):
    # group = {tz, winStart, winEnd, minFree}; ช่วงวันที่ ≤ 62 วัน
    memberSet = set(m.id for m in members)
    blocks    = [b for b in busyBlocks if b.userId in memberSet]
    timed     = [b for b in blocks if not b.allDay and b.endAt > b.startAt]   # ยาวศูนย์ = ไม่มีผล
    allDay    = [b for b in blocks if b.allDay]
    result = []
    for D in eachDate(fromDate, toDate):                       # PlainDate
        [w0, w1] = dayWindow(D, group.winStart, group.winEnd, group.tz)
        blockedAllDay = { b.userId for b in allDay if b.localStartDate <= D <= b.localEndDate }
        todays = [clip(b, w0, w1) for b in timed if b.startAt < w1 and b.endAt > w0]

        freeMembers = 0
        for m in members:
            if m.id in blockedAllDay: continue
            if any(len(s) >= minFree for s in subtract(w0, w1, [t for t in todays if t.userId == m.id])):
                freeMembers += 1

        if blockedAllDay is empty:
            segments = [s for s in subtract(w0, w1, todays) if len(s) >= minFree]
        else:
            segments = []
        result.append({ date: D, freeMembers, totalMembers: len(members),
                        allFree: len(segments) > 0, segments,
                        blockers: blockersOf(D) })          # U9.1 — ใครติด (กรองตาม ADR 0006 ภายหลัง)
    return result

function subtract(w0, w1, intervals):          # หน้าต่าง − ยูเนียนของ intervals (sweep)
    sort intervals by start
    free = []; cur = w0
    for [s, e] in intervals:
        if s > cur: free.append([cur, s])
        cur = max(cur, e)
    if cur < w1: free.append([cur, w1])
    return free
```
- `blockersOf(D)` = สมาชิกที่ไม่ว่างในวันนั้น พร้อม block ที่ทำให้ติด — ส่งออกเป็น `userId` + (ถ้าเห็นได้ตาม ADR 0006) `title` · คำนวณใน lib แต่ **ตัดรายละเอียดใน serializer** ไม่ใช่ใน lib
- เวลาในผลลัพธ์คืนเป็น instant (`EpochMs`) + ฟิลด์แสดงผล `HH:MM` ใน tz กลุ่ม (ปลายที่เป็นเที่ยงคืนถัดไปแสดง `24:00`)
- ความซับซ้อน: O(วัน × (busy ที่เกี่ยว log busy)) — กลุ่ม 50 คน × 62 วัน คำนวณในหน่วยมิลลิวินาที ไม่ต้อง cache

### 3. การดึงข้อมูล (Platform)
```sql
-- สมาชิกปัจจุบัน
SELECT user_id FROM group_member WHERE group_id = ?;
-- busy ที่อาจเกี่ยว (กรองหยาบด้วย start_at/end_at ที่คำนวณไว้ทั้ง timed และ all-day; ขยายขอบ ±14 ชม. เผื่อ tz ต่าง)
SELECT * FROM busy_block
 WHERE user_id IN (...) AND start_at < :rangeEndUtc + 14h AND end_at > :rangeStartUtc - 14h;
```
หน้าจอเดือนส่งช่วง `monthGrid()` ที่**เริ่มวันจันทร์** (ADR 0004 §5, boss 2026-10-16) เป็น `from/to` — ยาวไม่เกิน 42 วัน อยู่ในเพดาน 62 วัน · index `busy_block(user_id, start_at)` และ `(user_id, end_at)` รองรับ (ARCHITECTURE §3) · ฟังก์ชันใน lib เป็น pure — รับ array เข้า ไม่แตะ DB

### 4. ผลต่อ U10.1 (เตือนนัดทับ busy)
ใช้ `subtract`/overlap ตัวเดียวกัน: สมาชิกที่มี busy ทับ `[appt.start, appt.end)` หรือติดทั้งวันในวันท้องถิ่นใด ๆ ที่นัดครอบ → อยู่ในรายการเตือน (ไม่บล็อก) · รายละเอียดกรองตาม ADR 0006

## Alternatives considered
| ทางเลือก | ทำไมไม่เลือก |
|---|---|
| ตาราง slot 30 นาที (bitmap ต่อวัน) | ง่ายแต่ busy ใน tz อื่น/เวลาไม่ลงตัว 30 นาที (เช่น +05:45) จะคลาด และต้องแปลงกลับเป็นช่วงอีกรอบ · sweep บนช่วงจริงถูกต้องกว่าและสั้นพอกัน |
| คิด all-day เป็นช่วง UTC ตาม tz ของรายการ | คน BKK ลง "ทั้งวัน" แต่กลุ่มอยู่ tz อื่นจะปิดผิดวัน และไม่ตรงกับความหมาย "ทั้งวัน" ที่ผู้ใช้ตั้งใจ (ADR 0004) |
| นับสมาชิกตามประวัติ (เฉพาะช่วงที่เป็นสมาชิก) | ต้องเก็บประวัติ membership เพิ่ม และ PRD §5 พูดถึง "สมาชิกปัจจุบัน" ชัดเจน |
| "ว่าง X/Y" นับคนที่มี busy น้อยกว่า N ชม. | ไม่สอดคล้องกับนิยามกลุ่ม ใช้กฎขั้นต่ำเดียวกันทำให้ X/Y = Y/Y ⇔ คนละคนว่างแต่อาจไม่ตรงกัน — ซึ่ง UI ต้องอธิบาย (ดูข้อ Consequences) |

## Consequences
- + กฎเดียวทั้งกลุ่ม/รายคน/เตือนนัด · lib เป็น pure function ทดสอบด้วย fixture ได้ครบ
- − **"ว่าง 3/3" ไม่ได้แปลว่า "ว่างร่วม"** — ทุกคนอาจว่างคนละช่วง (เคส T24) → UI ต้องแยกสัญลักษณ์ "ว่างร่วม" ออกจากตัวเลข X/Y (แจ้ง UX)
- − busy 22:00–02:00 ไม่มีผลกับหน้าต่างดีฟอลต์เลย (T3) — ถูกตามนิยาม แต่ผู้ใช้อาจแปลกใจ
- − หน้าต่างข้ามเที่ยงคืนยังทำไม่ได้ใน v1
