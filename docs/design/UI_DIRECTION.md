## 1. หลักคิด
1. **ปฏิทินคือพระเอก** ไม่ใช่ตกแต่ง — พื้นที่หน้าจอส่วนใหญ่เป็นข้อมูล (วัน/คน/สถานะ) ความน่ารักมาจากสี น้ำเสียงข้อความ และแมวตัวเล็กๆ ไม่ใช่จากกล่องเงาและ gradient
2. **พาสเทลคือพื้นผิว ไม่ใช่ตัวหนังสือ** — สีพาสเทลใช้กับพื้นหลัง/ชิป/บล็อก ส่วนข้อความต้องเข้มพอ (≥ 4.5:1) เสมอ **ทั้งสองธีม**
3. **ลดจำนวนสิ่งที่ต้องตัดสินใจต่อหน้า** — หนึ่งหน้าหนึ่งงานหลัก หนึ่งปุ่มหลัก
4. **ไทยก่อน** — ออกแบบด้วยข้อความไทยจริง (วรรณยุกต์ ตัวยาว) ตั้งแต่ wireframe ห้ามใช้ lorem ipsum · แล้วตรวจซ้ำด้วยข้อความอังกฤษ (คำยาวกว่า)
5. **ธีมมืดคือธีมเดียวกันตอนกลางคืน** ไม่ใช่อีกแบรนด์ — โครง สัดส่วน ลำดับชั้นเหมือนกันทุกจุด เปลี่ยนแค่ค่าสี

## 2. อะไรคือ "AI slop" ที่ต้องเลี่ยง (ห้ามมีในงานส่ง)
- gradient ม่วง–น้ำเงิน/ชมพู–ส้ม, พื้นหลังเรืองแสง, glassmorphism/blur ซ้อนชั้น — **ยกเว้น aurora background ตาม §3.5 (boss สั่ง 2026-10-16)** ซึ่งได้รับอนุญาตเฉพาะเป็นชั้นพื้นหลังภายใต้กติกาใน §3.5 · gradient เป็นพื้นหลังของปุ่ม/การ์ด/ข้อความ ยังห้ามเหมือนเดิม
- การ์ดโค้งมนเท่ากันทุกใบ เงาฟุ้งหนา ซ้อนกันเป็นตาราง 3 คอลัมน์ซ้ำๆ
- อีโมจิเป็นไอคอนระบบ (✨📅🎉) และไอคอนคนละสไตล์ปนกัน
- หน้า hero กลางจอแบบ landing page + ปุ่ม CTA คู่ ในแอปที่ผู้ใช้ล็อกอินแล้ว
- ข้อความการตลาดฟุ้ง ("ยินดีต้อนรับสู่ประสบการณ์ใหม่!", "ปลดล็อกพลังการนัดหมาย" / "Unlock seamless scheduling!")
- ตัวเลข/สถิติปลอมเพื่อให้ดูแน่น, ภาพ stock, ภาพสร้างจาก AI ที่มีนิ้ว/ตัวอักษรเพี้ยน
- ฟอนต์ Inter + ตัวหนาทุกที่, ขนาดตัวอักษรเกือบเท่ากันหมดจนไม่มีลำดับ
- animation เด้ง/สั่น/ลอยตลอดเวลา, skeleton shimmer ทุกอย่าง
- ปุ่มเต็มความกว้างสีเดียวซ้อนกันหลายปุ่ม, toggle/pill เยอะจนไม่รู้ว่าอะไรกดได้
- dark pattern: ขอสิทธิ์/โชว์ modal ต้อนรับทันทีที่เปิด
- **ธีมมืด**: ดำสนิท `#000` หรือดำอมสีจางแบบแม่แบบ (`#0B0B0B`, `#111`), พาสเทลสดจ้าเรืองบนพื้นดำ, เงาดำที่มองไม่เห็นแทนการแบ่งชั้น
- **ภาษาอังกฤษ**: ALL CAPS ป้ายกำกับ, Title Case Every Word ในปุ่ม, ลูกศร "→" ต่อท้ายปุ่ม, คำแปลตรงตัวจากไทย ("Create appointment success")

## 3. ภาษาภาพ

### 3.5 Aurora background (boss สั่ง 2026-10-16 — มีผลเหนือ §2 เฉพาะเรื่องนี้)
ต้นแบบ: component "aurora background" จาก 21st.dev (ก้อนแสง radial-gradient เบลอหนักบนพื้นเข้ม) — ใช้เป็นแรงบันดาลใจเท่านั้น ไม่ใช้โค้ดต้นแบบ (ต้นแบบพึ่ง framer-motion และโหลด lottie-player จาก unpkg `@latest` ซึ่งห้าม)
- **เป็นชั้นพื้นหลัง (ambient) เท่านั้น** — `.aurora` `position: fixed` อยู่ใต้เนื้อหาทั้งหมด `pointer-events: none` · เนื้อหาที่ต้องอ่าน (การ์ดนัด, ช่องปฏิทิน, ฟอร์ม) อยู่บนพื้นทึบ `--surface` · แถบล่างและ bottom sheet ใช้ `--surface-veil` (กึ่งทึบ) + `backdrop-filter: blur(var(--veil-blur))` — สองที่นี้เท่านั้นที่ใช้ backdrop-filter
- **ข้อความที่วางบน aurora ตรงๆ**: หน้า "เข้ม" อนุญาตเฉพาะ `--ink` (ชื่อแอป, หัวข้อหน้า, ปุ่มภาษา) · หน้า "จาง" อนุญาต `--ink`, `--ink-muted`, `--accent-ink` · ทุกกรณีคำนวณจาก **กรณีแย่สุด** = ก้อนแสงทุกชุดย่อยซ้อนกันที่จุดกลาง (`contrast.mjs`) · ปุ่มหลักไม่วางบน aurora ตรงๆ (อยู่บน veil หรือ surface)
- **สี**: ม่วงคราม (accent) + เขียว (free) + ฟ้า (event) + ชมพูหม่น (busy) — ไม่ใช้ lime/magenta ของต้นแบบ · token `--aurora-1…4` (rgba, alpha = ค่าที่จุดกลางก้อน) ทั้งสองธีม · ธีมมืดใกล้ต้นแบบที่สุด (ก้อนแสงบนถ่านอมม่วง) · ธีมสว่างเป็นพาสเทลบนขาวอุ่น
- **ความเข้มตามหน้า** (`<body data-aurora="hero|soft">`): **hero** (`--aurora-hero` = 1) หน้าเข้าสู่ระบบ/สมัคร, หน้าว่าง, หน้าสำเร็จหลังสร้างนัด, หน้าหลัก (หลังการ์ดนัดถัดไป) · **soft** (`--aurora-soft` สว่าง 0.24 / มืด 0.35) หน้าปฏิทิน, ฟอร์ม, รายการ — ข้อมูลมาก่อน · หน้า admin ไม่มี aurora
- **ทำด้วย CSS ล้วน**: ก้อนแสง ≤ 4 ก้อน (radial-gradient มีช่วงสีเต็ม 30% แรก) · `filter: blur(var(--aurora-blur))` บน **เลเยอร์เดียว** (`.aurora-field`) · ก้อนเคลื่อนด้วย `transform` เท่านั้น `will-change: transform` รอบละ 28–44 วินาที (`--aurora-dur-*`) ไป-กลับ ไม่มี JS · `prefers-reduced-motion` → หยุดนิ่ง
- ห้าม: aurora หลังข้อความ `--ink-muted` ในหน้า hero, gradient บนปุ่ม/การ์ด, glass ซ้อนหลายชั้น, แสงกะพริบ/เปลี่ยนสีเร็ว, aurora ในหน้า admin

## 4. โครงหน้าและรูปแบบบนมือถือ
- **ตำแหน่งหัวแม่มือ**: แถบนำทางล่าง 4 แท็บ (หน้าหลัก · ปฏิทิน · กลุ่ม · ฉัน) · การกระทำหลักเป็นปุ่มลอยมุมล่างขวาหรือปุ่มใน bottom sheet ไม่วางไว้ข้างบน
- **สร้าง/แก้ทุกอย่างด้วย bottom sheet** ปัดลงปิดได้ ไม่เปลี่ยนหน้าโดยไม่จำเป็น · sheet ข้อมูลวัน = ครึ่งจอ (ยังเห็นแถววันที่แตะ) · sheet ฟอร์ม = เกือบเต็มจอ ปุ่มหลักติดด้านล่าง
- **หน้าหลัก**: ด้านบนเป็นการ์ด **"นัดถัดไป"** (แถบนับถอยหลังสี `--event` + ชื่อ, เวลา, สถานที่ + เปิดในแอปแผนที่, กลุ่ม, คนไป/อาจไป/ยังไม่ตอบ, ปุ่มตอบของฉัน) ถัดลงมารายการนัดที่เหลือข้ามทุกกลุ่มแบบแถวเรียบๆ · ไม่มีนัด → หน้าว่าง + แมว + ปุ่ม "ดูวันที่ว่างตรงกัน"
- **ปฏิทินเดือน**: **สัปดาห์เริ่มวันจันทร์** (จ … อา / Mon … Sun — boss ตัดสิน 2026-10-16) · แต่ละวันแสดงความว่างของกลุ่มเป็น 4 ระดับ + ตัวเลข **"5/6"** (ช่องกว้าง ≈ 46px ที่ 375 ใส่คำว่า "ว่าง" ไม่พอ — คำอธิบายตัวเลขอยู่ใต้ปฏิทิน และ aria-label อ่านเต็ม "24 ตุลาคม ว่าง 6 จาก 6 คน") · แตะวัน → bottom sheet: ช่วงที่ทุกคนว่างพร้อมกัน + รายชื่อสมาชิกพร้อมช่วงที่ติด (ตามสิทธิ์การมองเห็น; ซ่อนรายละเอียด = "ไม่บอกรายละเอียด") + ปุ่ม "สร้างนัดวันนี้"
- **ลง busy**: เลือกช่วงวันด้วยการแตะวันเริ่ม–วันจบบนปฏิทิน (ไม่ใช้ date picker ของระบบ) · สวิตช์ "ทั้งวัน" · ถ้าไม่ทั้งวันจึงโชว์ช่องเวลาเริ่ม–จบ (ทีละ 30 นาที) · ช่อง "ทำอะไร" + สวิตช์ "ไม่บอกรายละเอียด" · บอกชัดว่า "ทุกกลุ่มที่คุณอยู่จะเห็นช่วงนี้" (D5)
- **ช่อง PIN**: แป้นตัวเลขของเราเองขนาดใหญ่ (ปุ่ม ≥ 56px) 6 จุดแสดงความคืบหน้า ไม่แสดงตัวเลขที่กด · ผิดแล้วบอกตรงๆ และบอกจำนวนครั้งที่เหลือ/เวลารอเมื่อถูกล็อก
- **iPad (≥ 768px)**: สองคอลัมน์ (ปฏิทิน + แผงรายละเอียดวัน `--split-side` 320px) แทน sheet · ฟอร์มยังเป็น sheet กว้าง `--content-max` กลางจอ · ไม่ขยายองค์ประกอบมือถือให้ใหญ่ขึ้นเฉยๆ
- **ภาษาและธีม**: ตั้งในแท็บ "ฉัน" → หัวข้อ "การแสดงผล" (ภาษา: ไทย / English · ธีม: ตามเครื่อง / สว่าง / มืด) แบบ segmented ทันทีไม่ต้องกดบันทึก · หน้าเข้าสู่ระบบมีปุ่มสลับภาษาเล็กมุมบน (TH | EN) · ธีมตั้งก่อน paint ด้วย `data-theme` บน `<html>`
- **หน้า admin**: ตารางกะทัดรัดที่ใช้งานจริง (ค้นหา, กรอง, สถานะ) จริงจังกว่า ไม่ใส่แมว
- ทุกหน้าต้องออกแบบครบ 4 สถานะ: **โหลด · ว่าง · ปกติ · ผิดพลาด** (wireframe ใน [UX.md §3](UX.md))

## 5. การเคลื่อนไหว
- 150–220ms (`--dur-fast` / `--dur` / `--dur-slow`), `--ease-out` ใช้กับการเปิด/ปิด sheet, การเลือกวัน, การเปลี่ยนแท็บ เท่านั้น
- เคารพ `prefers-reduced-motion` (token ระยะเวลาเป็น 0 อัตโนมัติ)
- ห้ามแอนิเมชันที่วนเองตลอด ยกเว้นตัวโหลดสั้นๆ · โหลด = กล่องนิ่งสี `--surface-2` + ข้อความ "กำลังโหลด…" ไม่มี shimmer
- สลับธีมไม่ทำ transition สี (กันกระพริบ)

## 6. ข้อความ (microcopy)
### 6.1 ภาษาไทย
- น้ำเสียง: เป็นกันเอง สุภาพ กระชับ ไม่ตื่นเต้นเกินเหตุ ไม่ใช้ "ค่ะ/ครับ" แบบบังคับเพศของแอป · ไม่แปลตรงจากอังกฤษ
- ปุ่มเป็นกริยาสั้น: "ลงวันไม่ว่าง", "สร้างนัด", "คัดลอกโค้ดเชิญ", "ส่งคำขอ"
- ข้อผิดพลาดบอกว่าเกิดอะไรและทำอะไรต่อ: "PIN ไม่ถูกต้อง เหลืออีก 3 ครั้ง" ไม่ใช่ "เกิดข้อผิดพลาด"
- หน้าว่าง: บอกสถานะ + ทางไปต่อ 1 อย่าง เช่น "ยังไม่มีนัดเลย — ดูวันที่ทุกคนว่างตรงกัน"
- ห้ามอีโมจิในปุ่ม/หัวข้อระบบ (ในข้อความที่ผู้ใช้พิมพ์เองไม่เกี่ยว)
- วันที่: พ.ศ. + ชื่อเดือนไทยย่อ "ส. 17 ต.ค. 2569" (เต็มในหัว sheet "เสาร์ 24 ตุลาคม 2569") · เวลา 24 ชม. "18:00–21:00" ใช้ en dash
### 6.2 ภาษาอังกฤษ
- น้ำเสียงเหมือนเพื่อนที่จัดทริปเก่ง: สั้น ธรรมดา ไม่ขาย · sentence case ทุกที่ (ปุ่ม หัวข้อ แท็บ) · ใช้ contraction ได้ ("Can’t go", "Couldn’t load")
- คำศัพท์หลักคงที่ทั้งแอป: **plan** (นัด), **busy time** (ช่วงไม่ว่าง), **free** (ว่าง), **group**, **invite code**, **Going / Maybe / Can’t go** (RSVP) — ปุ่ม "Create plan" → ข้อความสำเร็จ "Plan created"
- เขียนใหม่ ไม่แปลตรง: "ดูวันที่ว่างตรงกัน" → "Find a free day" (ไม่ใช่ "See matching free dates") · "อีก 2 วัน" → "In 2 days" · "ไม่บอกรายละเอียด" → "Details hidden"
- วันที่: ค.ศ. "Sat 17 Oct 2026" (วันก่อนเดือน แบบสากล/อังกฤษ ไม่ใช้ 10/17) · เวลา 24 ชม. เหมือนไทย
- ข้อมูลที่ผู้ใช้พิมพ์ (ชื่อคน ชื่อกลุ่ม ชื่อนัด สถานที่) **ไม่แปล** — หน้าอังกฤษจึงมีไทยปนเป็นปกติ ฟอนต์เดียวรองรับทั้งคู่
- ตาราง microcopy คู่ TH/EN ที่ต้องใช้คำนี้เท่านั้น: [UX.md §4](UX.md)

## 8. Anti-slop checklist (QA reviewer ตรวจ แนบภาพหน้าจอ ทุกหน้าที่เปลี่ยน — ครบ 4 ชุด TH/EN × สว่าง/มืด)
