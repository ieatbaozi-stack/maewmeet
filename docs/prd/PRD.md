## 3. บทบาทและเมทริกซ์สิทธิ์ (ฉบับสุดท้าย — ฐานของเทสต์ role × action)
บทบาท: **Super admin** (`is_admin = 1` ตั้งเองใน DB) · **Group admin** (ผู้สร้างกลุ่ม, กลุ่มละ 1 คน) · **Moderator** (admin แต่งตั้ง) · **Member** · **ไม่ใช่สมาชิก** (ล็อกอินแล้วแต่ไม่อยู่กลุ่มนั้น) · **ไม่ได้ล็อกอิน**

✅ ทำได้ · ❌ ทำไม่ได้ · ตัวเลขในวงเล็บ = อ้างอิงข้อตัดสินใจ

กติกาเสริม:
- ระหว่างคำขอ reset รออนุมัติ: ไม่มีสถานะพิเศษ — จำ PIN เดิมได้ก็เข้าใช้ได้ทุกอย่าง จำไม่ได้ก็เข้าไม่ได้ (boss ยืนยัน)
- ผู้ใช้สถานะ `must_change_pin` (เข้าด้วย `123456` แล้ว) ทำได้อย่างเดียวคือตั้ง PIN ใหม่ / ออกจากระบบ — ทุก action อื่นในตารางถูกปฏิเสธ
- super admin ที่ไม่ได้เป็นสมาชิกกลุ่ม: ดู/จัดการได้ผ่านหน้า admin แต่ไม่ถูกนับในการคำนวณวันว่างร่วม และไม่ RSVP
- ทุกการกระทำของ super admin ต่อกลุ่ม/ผู้ใช้อื่น ลง audit log

## 4. User stories และเกณฑ์รับ
รูปแบบเกณฑ์: ตรวจได้ด้วยเทสต์ (unit/integration/E2E) — contract แต่ละรอบจะอ้างเลขเหล่านี้

### บัญชี (R1)
- **U1** สมัครด้วย username + ชื่อที่แสดง + PIN 6 หลัก (ยืนยัน 2 ครั้ง) แล้วล็อกอินด้วย username + PIN
  - AC: username ซ้ำ (ไม่สนตัวพิมพ์) ถูกปฏิเสธ · PIN ต้องเป็นตัวเลข 6 หลัก · ปฏิเสธ PIN `123456` และ PIN ตัวเลขเรียงหรือซ้ำทั้งหมด (เช่น 000000, 654321) ตอนตั้งเอง · สมัครถูกจำกัดความถี่ต่อ IP
  - AC: ล็อกอินผิด → ข้อความเดียวกันไม่ว่า username ไม่มีหรือ PIN ผิด · ผิดเกินเกณฑ์ → ล็อกชั่วคราวแบบเพิ่มเวลา ต่อ username และต่อ IP (ค่าตัวเลขกำหนดใน ADR auth)
  - AC: session อยู่ได้นาน (ดีฟอลต์ 60 วัน) · ออกจากระบบทุกเครื่องได้
- **U2** ลืม PIN → ส่งคำขอ reset ด้วย username → super admin อนุมัติ/ปฏิเสธ → ถ้าอนุมัติ PIN กลายเป็น `123456`
  - AC: ส่งคำขอได้แม้ไม่ได้ล็อกอิน · หน้าตอบข้อความเดียวกันไม่ว่า username มีหรือไม่ · มีคำขอค้างได้ 1 รายการต่อผู้ใช้
  - AC: ระหว่างรออนุมัติ PIN เดิมยังล็อกอินได้ตามปกติ และ `123456` ยังใช้ไม่ได้ · ถ้าล็อกอินด้วย PIN เดิมสำเร็จ คำขอที่ค้างถูกยกเลิกอัตโนมัติ (เจ้าตัวจำได้แล้ว — กันไม่ให้เปิดช่อง `123456` โดยไม่จำเป็น) และแจ้งในแอป
  - AC: อนุมัติแล้ว `123456` ใช้ได้ภายใน 24 ชม. (D3) · เกินแล้วคำขอเป็น `expired` ต้องขอใหม่ · ล็อกอินด้วย `123456` สำเร็จ = คำขอเป็น `used`
  - AC: ทุกการอนุมัติ/ปฏิเสธลง audit log (ใคร, เมื่อไร, ของใคร)
- **U3** หลัง super admin อนุมัติ ผู้ใช้เข้าด้วย `123456` แล้วระบบพาไปหน้าตั้ง PIN ใหม่ทันที ก่อนทำอย่างอื่นได้
  - AC: ทุก API นอกจาก "ตั้ง PIN ใหม่" และ "ออกจากระบบ" ตอบ 403 ระหว่าง `must_change_pin` · PIN ใหม่ห้ามเป็น `123456`

### กลุ่ม (R2)
- **U4** สร้างกลุ่ม → ผู้สร้างเป็น group admin
- **U5** ชวนเข้ากลุ่ม (ก) ชวนตรงถึง username → อีกฝ่ายเห็นคำเชิญในแอปแล้วกดรับ/ปฏิเสธ (ข) สร้างโค้ดเชิญ → คัดลอก/แชร์ → อีกฝ่ายพิมพ์โค้ดแล้วเข้ากลุ่มทันที (D6)
  - AC: โค้ดสุ่ม ≥ 8 ตัว (ตัดตัวที่สับสน เช่น 0/O, 1/I) · เก็บเป็น hash · หมดอายุ 7 วัน · เพิกถอนได้ · พิมพ์ผิดถูกจำกัดความถี่ต่อผู้ใช้และ IP · โค้ดหมดอายุ/เพิกถอน/ไม่มีจริง ตอบข้อความเดียวกัน
  - AC: ใช้โค้ดของกลุ่มที่เป็นสมาชิกอยู่แล้ว → ไม่สร้างแถวซ้ำ
- **U6** admin/moderator ลบสมาชิก (ตาม D7), แก้ชื่อกลุ่ม · admin แต่งตั้ง/ปลด moderator, โอน admin, ลบกลุ่ม · สมาชิกออกจากกลุ่มเองได้ (admin ต้องโอนก่อน — D8)
  - AC: ลบกลุ่มเป็น soft delete (`deleted_at`) ลง audit log · คนที่ถูกลบออกเห็นข้อมูลกลุ่มไม่ได้ทันที (เทสต์)

### ปฏิทิน (R3)
- **U7** ลงช่วงไม่ว่าง 3 แบบ: หลายวันติดกัน / ทั้งวัน / ช่วงเวลาในวัน (ทีละ 30 นาที) พร้อม "ทำอะไร" (ไม่บังคับ) และตัวเลือก "ซ่อนรายละเอียด"
  - AC: ช่วงหลายวัน = 1 รายการ · end > start (ช่วงเวลา) หรือ end ≥ start (วันที่) · รองรับข้ามเที่ยงคืน ข้ามเดือน/ปี ปีอธิกสุรทิน
  - AC: busy ลงครั้งเดียวแสดงในทุกกลุ่มที่ผู้ใช้อยู่ (D5) · รายการที่ซ่อนรายละเอียด API ส่งแค่ "ไม่ว่าง" ให้คนอื่น (ไม่ใช่ซ่อนแค่ที่ UI)
- **U8** ปฏิทินกลุ่มมุมมองเดือนและวัน เห็นว่าใครไม่ว่างเมื่อไร
  - AC: เห็นได้เฉพาะสมาชิกกลุ่ม · ไม่ใช่สมาชิกได้ 403/404 (เทสต์)

### วันว่างร่วม + นัด (R4)
- **U9** ระบบแสดงวันที่ทุกคนว่าง และช่วงว่างในวันนั้น → กด "สร้างนัด" จากวันนั้น
  - AC: ผลตรงกับตัวอย่างที่คำนวณมือใน [RESEARCH_REPORT ข้อ 5](../research/RESEARCH_REPORT.md) ทุกกรณี
- **U9.1** ถ้าไม่มีวันว่างครบ แสดง "ว่าง X/Y" รายวัน + ใครติด (ตามสิทธิ์การมองเห็น)
- **U10** สร้างนัด: ชื่อกิจกรรม, วัน-เวลาเริ่ม/จบ, สถานที่ (ชื่อ + พิกัดหรือลิงก์แผนที่, ไม่บังคับ), รายละเอียด
  - AC: ค้นหาสถานที่แบบกดค้นหา (ไม่ autocomplete ทุกตัวอักษร) หรือวางลิงก์/พิกัด · แผนที่ OSM · ปุ่มเปิดในแอปแผนที่ของเครื่อง
- **U10.1** RSVP: ไป / อาจไป / ไม่ไป · เตือน (ไม่บล็อก) ถ้านัดทับ busy ของสมาชิก
- **U10.2** แก้/ยกเลิกนัด ตาม D4 · นัดที่ยกเลิกยังเห็นได้พร้อมสถานะ

### หน้าหลัก (R4)
- **U11** เปิดแอปเห็น **นัดถัดไป** เป็นการ์ดใหญ่ (ชื่อ, วัน-เวลา, สถานที่, อีกกี่วัน, จำนวนคนไป) + รายการนัดที่เหลือข้ามทุกกลุ่ม · ไม่มีนัด → หน้าว่าง + แมว + ปุ่ม "ดูวันที่ว่างตรงกัน"

### ผู้ดูแลระบบ (R1 บางส่วน, R5 เต็ม)
- **U12** หน้า super admin: รายการคำขอ reset (อนุมัติ/ปฏิเสธ) · ผู้ใช้ทั้งหมด (ค้นหา, ระงับ, ปลดล็อก) · กลุ่มทั้งหมด (ดู, โอน admin, ลบ) · audit log
  - AC: R1 ทำเฉพาะส่วน reset · R5 ทำส่วนที่เหลือ

### บัญชีของฉัน (R5)
- **U13** เปลี่ยนชื่อที่แสดง, เปลี่ยน PIN (ต้องใส่ PIN เดิม), ออกจากระบบทุกเครื่อง, ลบบัญชี (ต้องโอน admin ของทุกกลุ่มก่อน) + ประกาศความเป็นส่วนตัวสั้นๆ

### R6 hardening backlog (Low ที่เลื่อนจากการตรวจ R2)
รายการที่ตั้งใจเลื่อนมาทำใน R6 — ไม่บล็อก R2:
- [ ] rate limit การเขียนต่อผู้ใช้ สำหรับสร้าง/เพิกถอนกลุ่มและโค้ดเชิญ (ตอนนี้จำกัดด้วยเพดานจำนวนเท่านั้น)
- [ ] job ลบถาวรตามอายุ (retention) สำหรับกลุ่มที่ soft delete และคำเชิญเก่า — ตามหลัก PDPA (เก็บเท่าที่จำเป็น)
- [ ] คิว `serialized` แย่งกันตอนใช้โค้ดแล้วเจอ 429 — เพิ่ม pre-check ราคาถูกก่อนเข้าคิว
- [ ] การลบออกจากกลุ่มไม่ใช่การแบน (ผู้ถูกลบใช้โค้ด/รับคำเชิญกลับเข้ามาได้) — พิจารณา deny list แบบเลือกได้
- [ ] ผู้รับปิดรับคำเชิญตรง (invite opt-out)
- [ ] ชื่อกลุ่มที่หน้าตาคล้ายกัน (confusable / homoglyph) — ตอนนี้กันแค่ตัวมองไม่เห็น/bidi
- [ ] ลิมิตการใช้โค้ดผิดแบบรวมทั้งระบบ (global failed-redeem limit) นอกเหนือจากต่อผู้ใช้/ต่อ IP
- [ ] e2e ตั้ง `retries: 2` ซึ่งอาจบังเทสต์ที่ไม่นิ่ง (flaky) — ไล่ปิดแล้วลดเหลือ 0 ใน CI
- [ ] guard ตอบ HTTP 200 ก่อน (streaming) แล้วค่อย redirect — ตรวจว่า status ที่ client เห็นตรงกับที่ตั้งใจ
